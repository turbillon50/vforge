# Recuperación documental y herramientas de V — 30 octubre 2026

La casa canónica usa fuentes históricas con autor, fecha y procedencia. Esta intervención conserva los registros originales y añade consulta y herramientas; no certifica que se haya recuperado toda la historia de V.

## Comparación de respaldos

Se leyeron archivos de Hetzner como datos COPY, sin ejecutar el SQL de los dumps. Las 22,936 filas de VIEJA-cerebro, las 1,443 de julio y las 8,789 del corte de octubre ya estaban representadas por contenido en memory o memory_archivo_vigia. No se reimportaron esos bloques ni el ruido automático del Vigía.

REAL-cerebro contiene 159 filas: 21 contenidos ya presentes y 138 que no estaban en esas tablas. Junto con 221 versiones de brain_files, se conservaron 359 registros en la tabla aditiva v_recovery_archive. Veintinueve copias tuvieron credenciales detectadas y ocultadas; los dumps originales permanecen intactos. Se guardan hash original, ID, autor, fecha y archivos de procedencia. Los autores distintos de V se conservan como tales.

La fuente original exacta del 2 de mayo sigue pendiente. Una fecha de commit no demuestra que exista una conversación de esa fecha.

## Herramientas

- v_memoria_buscar, v_memoria_leer y v_memoria_fuentes consultan el índice existente y la recuperación; exponen referencias y fechas, no convierten declaraciones antiguas de un asistente en hechos verificados.
- db_schema por conexión descubre el nombre real de la base, tablas y columnas. La etiqueta editable no prueba qué base está conectada. PostgreSQL opera mediante transacciones de sólo lectura.
- Cerebras auxilia búsqueda, organización con IDs de origen y preparación de gráficas. Las cifras de gráficas de consultas se extraen en servidor del resultado real; las cifras aportadas manualmente se etiquetan como no verificadas contra una base. No se ejecuta código de modelos o repositorios.
- Los artefactos de gráficas se guardan por mensaje/sesión y se recuperan al abrir el hilo. La UI los dibuja con SVG y permite inspeccionar los datos.
- GitHub usa una credencial compartida cifrada o la conexión del servidor; el token no se devuelve al cliente. V lista y lee repositorios autorizados con paginación, respetando el permiso del token. Se pueden clasificar como skills, componentes, ejemplos, módulos de IA o referencia.
